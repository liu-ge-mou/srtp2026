## 文件中的计算顺序

1. X(3,4) 与四个 4×4 权重生成 Q、K、V、S(3,3)、P(3,3) 和注意力输出(3,4)。
2. S[i,j] 是第 i 个 token 的查询与第 j 个 token 的键的匹配分数；P[i,j] 是聚合第 j 个 token 的值向量时所用的权重。P 的每行和为 1。
3. H1 = LayerNorm(X + Attention(X))。
4. FFN 将 H1 从 (3,4) 变到 (3,8)，经 ReLU 后变回 (3,4)。
5. H2 = LayerNorm(H1 + FFN(H1))。

check_example 检查形状、P 的行和、LayerNorm 行均值、有限值，以及修改第一个 token 后的输出变化。代码和运行通过只代表此示例已验证，不代表学习者独立完成手算或编程。

## QKV 融合

qkv_fusion.py 对应原始实验要求“题目二 → 4. 基础优化：QKV 融合”的第 1、2 项。Wq、Wk、Wv 各为 (4,4)，沿列拼接得到 Wqkv(4,12)。X(3,4) 乘一次 Wqkv 后得到 (3,12)，沿最后一维切成三个 (3,4)。

脚本比较 Q、K、V、注意力输出和完整 Block 输出。当前输入的最大绝对误差均为 0.0。QKV 投影的矩阵乘法调用次数从 3 次变为 1 次；理论 MAC 次数仍为 144。权重拼接发生在投影之前。这里没有计时，也没有证实实际运行加速；性能测量是任务清单的下一项。

### 可手算的拼接例子

取 X = [[1, 2]]，三个 2×2 权重分别为 Wq = [[1,0],[0,1]]、Wk = [[0,1],[1,0]]、Wv = [[2,0],[0,3]]。分开计算得到 Q = [[1,2]]、K = [[2,1]]、V = [[2,6]]。

按列拼接后 Wqkv = [[1,0,0,1,2,0],[0,1,1,0,0,3]]，所以 X @ Wqkv = [[1,2,2,1,2,6]]。按每 2 列切分，恰好得到相同的 Q、K、V。一般形式为 X @ [Wq | Wk | Wv] = [X @ Wq | X @ Wk | X @ Wv]；融合只把三次投影矩阵乘法调用合为一次，乘加项数不变。

### 这份代码的编写顺序

1. 先把原始要求第 4 节第 1 项拆成五个可检查的结果：Q、K、V、注意力输出和完整 Block 输出。前两种实现必须使用相同的 X 与权重，否则不能比较。
2. 在 qkv_fusion.py 的 main 中先写分开计算 Q_separate、K_separate、V_separate，作为基线。make_example 复用基础脚本的固定种子和权重。
3. 用 np.concatenate([Wq, Wk, Wv], axis=-1) 沿列拼接。Wqkv 在调用 project_qkv_fused 前生成；该函数只执行 x @ Wqkv 和按最后一维三等分。这样后续做性能实验时，能够把拼接放在计时区间之外。
4. 先逐一比较 Q、K、V，再用同一 Wo 比较注意力输出，最后用同一 FFN 权重比较 Post-LN Block 输出。np.allclose 使用 rtol=1e-12、atol=1e-12；打印最大绝对误差，便于定位差异。
5. 最后写计算量说明。对 X(N,d) 和三个 (d,d) 权重，分开与融合的投影都需要 3Nd² 次理论 MAC；只是 NumPy 矩阵乘法调用从 3 次变为 1 次。这里的运行结果不能代替计时结论。

## QKV 性能测量

qkv_benchmark.py 对应原始要求“题目二 → 4. 基础优化：QKV 融合”的第 3～5 项。输入 X 为 (128,64)，三组权重均为 (64,64)。Wqkv 在计时前沿列拼接为 (64,192)。计时前先检查分开与融合计算的三个输出均为 (128,64) 且数值接近。

编写顺序：先定义分开投影函数；复用 qkv_fusion.py 的融合投影函数；在 main 中固定随机种子并生成同一组输入和权重；定义两个无参数的运行函数，让统一的 time_batch 接受函数并测量；将拼接与正确性检查放在计时外；两种实现各预热 20 次，然后交替计时 9 组，每组运行 200 次；每组总时间除以 200，最后取 9 个每次调用时间的中位数。

计时只包含 QKV 投影及融合后的切分。分开版进行三次矩阵乘法；融合版进行一次较宽的矩阵乘法及 np.split。两者理论 MAC 数均为 3×128×64² = 1,572,864。计时结果会受 CPU、NumPy 的矩阵乘法实现、线程调度和系统负载影响。一次运行的时间比值不能证明普遍加速；函数调用减少也不代表理论乘加次数减少。

2026-10-12 在 Python 3.14.6、NumPy 2.4.6 下的一次运行：Q/K/V 最大绝对误差 8.881784197001252e-15；分开 46.550 微秒/次，融合 29.099 微秒/次，比值 1.600。同一脚本另一运行得到分开 44.078、融合 33.469 微秒/次，比值 1.317。两次数字不同，均只作为本机记录。

## 因果自注意力

causal_attention.py 对应原始要求“题目二 → 5. 软件部署小实验 → 方向 A：简单 KV Cache”的单层因果自注意力前提。该脚本实现整段输入的因果注意力；逐 Token 重算和缓存实现见后续两节。

设计与数据流：复用 transformer_numpy.py 的稳定 softmax 和固定种子示例；输入 X(N,d)、四个 (d,d) 权重，先算 Q/K/V(N,d)，再算 scores=Q@K.T/√d(N,N)。行 i 是当前 Token，列 j 是可读取的 Token。np.triu(..., k=1) 标出 j>i 的未来位置；np.where 把这些分数改为 -inf；最后逐行 softmax 得到 weights(N,N)，输出 (weights@V)@Wo(N,d)。掩码必须在 softmax 前应用；事后清零概率会破坏行和为 1。

手算例子：X=[[1,0],[0,1],[1,1]]，四个权重都为 2×2 单位阵。scores=XXᵀ/√2。第 0 行仅允许 j=0，权重 [1,0,0]，输出 [1,0]。第 1 行允许 j=0,1，分数为 0、1/√2，权重约 [0.3302,0.6698,0]。第 2 行允许所有位置，权重约 [0.2483,0.2483,0.5035]。k=1 从主对角线上方开始标记，因此当前位置仍可见；axis=-1 让 softmax 逐行归一化。

检查：形状、未来权重严格为 0、权重非负、每行和约为 1、概率和输出有限；比较完整序列与各前缀输出，改动最后一个 Token 后确认前面位置输出不变。masked_scores 的禁用项故意是 -inf，不能对整个 masked_scores 作有限值断言；每行都包含当前位置，不会出现全 -inf 行。此脚本未实现 KV Cache，也不代表学习者独立掌握。

在仓库根目录运行 python software/causal_attention.py。2026-10-12 在 Python 3.14.6 与 3.13.3、NumPy 2.4.6 下均打印 PASS；3×4 示例权重约为 [[1,0,0],[0.6092,0.3908,0],[0.0533,0.0081,0.9386]]。

## 逐 Token 重算 K/V 基线

kv_recompute.py 对应原始要求“题目二 → 5 → 方向 A：简单 KV Cache”的第 1 项。本脚本实现每步重算 K/V 的基线；缓存版见下一节，两版实际耗时见最后一节。输入沿用 X(N,d) 和相同的四个 (d,d) 权重，每一步只输出新 Token 的一行 (1,d)，最后用 np.vstack 拼成 (N,d)。

设计顺序：第 end 步取 current=X[end-1:end]，形状 (1,d)，只投影当前的 Q；取 history=X[:end]，形状 (end,d)，每一步重新投影所有历史及当前的 K、V，形状均为 (end,d)。然后算 scores=q@K.T/√d，形状 (1,end)，沿最后一维 softmax 得到 (1,end) 权重，输出 (weights@V)@Wo，形状 (1,d)。history 已经截断到当前位置，没有未来 Token，因此这一步不需要额外掩码。注意切片 end-1:end 保留二维形状；若取 X[end-1] 会得到一维向量，后续形状和整段基线不同。

三 Token、二维单位权重例子：第 1 步只看 [1,0]，输出 [1,0]；第 2 步的当前 Q=[0,1]，历史 K 为 [[1,0],[0,1]]，分数 [0,1/√2]，softmax 权重约 [0.3302,0.6698]，输出也约 [0.3302,0.6698]。第 3 步重新计算三行 K 和 V。二维例子的每步 K/V 元素数为 [4,8,12]，累计 24；每个 Token 只算一次需 12，故重复计算了 12 个。

一般地，第 t 步（t 从 1 开始）的 K/V 投影输出有 2td 个元素；T 步累计 2d(1+...+T)=dT(T+1) 个，只算一次则是 2dT 个，重复元素数为 dT(T-1)。这只是 K/V 投影输出元素计数，不是矩阵乘法 MAC 数或运行时间。固定示例 T=3、d=4，三步为 [8,16,24]，累计 48、只算一次 24、重复 24。

检查顺序：先用同一 X 与权重算完整因果注意力；逐行比较逐步输出；再核对每步、累计与重复元素数，最后用二维手算例子检查前两步。运行 python software/kv_recompute.py：2026-10-12 在 Python 3.14.6 / NumPy 2.4.6 下最大绝对误差 0.0，在 Python 3.13.3 / NumPy 2.4.6 下为 1.7763568394002505e-15，两次均 PASS。

## KV Cache 增量计算

kv_cache.py 对应原始要求“题目二 → 5 → 方向 A”第 2、3 项：把历史 K/V 存起来，新一步只计算当前 Token 的 K/V，并与重算版比较每一步输出。仍使用 X(N,d) 与四个 (d,d) 权重；同一组输入、权重和 softmax 是比较的前提。

设计：先分配 K_cache、V_cache 两个 (N,d) 数组。第 end 步取 current=X[end-1:end]，形状 (1,d)，计算当前的 q、k_new、v_new。把 k_new、v_new 写入缓存的 end-1 行；随后只读取 K_cache[:end]、V_cache[:end]，形状 (end,d)。这些切片恰好包含当前和过去的值，未写入的后续行不参与运算。scores=q@K.T/√d 为 (1,end)，softmax 后经 (weights@V)@Wo 输出 (1,d)。每步输出最后用 np.vstack 合为 (N,d)。预分配避免每一步为了扩展缓存而重新拼接整个数组；当前例子预先知道长度 N。此函数现也返回两块缓存数组的 cache_bytes；容量核算和完整解码计时见最后一节。

三 Token、二维单位权重例子：第 1 步缓存 K/V 各为 [[1,0]]；第 2 步只计算新行 [0,1] 并写入，已写入的 K/V 变为 [[1,0],[0,1]]。当前 q=[0,1]，分数 [0,1/√2]，输出约 [0.3302,0.6698]，与重算版一致。第 3 步仍只投影一行。该例每步新算 K/V 元素数为 [4,4,4]，重算版为 [4,8,12]。

固定 X(3,4) 时，缓存版每步为 [8,8,8]，累计 24、重复 0；重算版为 [8,16,24]，累计 48、重复 24。检查逐步输出与重算版、整段因果注意力均接近，并单独打印最后一个 Token 的最大绝对误差。运行 python software/kv_cache.py：2026-10-12 在 Python 3.14.6、NumPy 2.4.6 下逐步/最后误差均 0.0；在 Python 3.13.3、NumPy 2.4.6 下分别约 2.22e-16 / 6.94e-17；两次均 PASS。这些数值检查不证明实际运行加速。

## KV Cache 容量与完整解码计时

kv_benchmark.py 对应原始要求“题目二 → 5 → 方向 A”第 4、5 项与学习清单中的实际时间报告。先复用两版解码函数检查相同输入与权重下的输出，再用 cache_capacity_bytes(T,d,dtype) 计算 2*T*d*itemsize，并与缓存函数返回的两数组 nbytes 之和核对。

原始容量公式为 2*B*L*T*Hkv*dh*s。2 表示 K 和 V；B 为批量、L 为层数、T 为历史长度、Hkv 为 KV 头数、dh 为每头维度、s 为元素字节。当前 B=L=Hkv=1、dh=d，故 X(3,4)、float64 的数据容量为 192 字节；float32 同形状为 96 字节。实际解码缓存采用预分配，第 1 步已经分配整段容量，但只读取已写入的前缀。nbytes 只计数组数据区域，不是进程峰值内存。

代码按“生成共享输入 → 输出及容量检查 → 定义完整解码调用 → 每种预热 10 次 → 交替测 9 组、每组 20 次 → 每组平均后取中位数 → 打印”执行。time_batch 返回每次完整解码的纳秒数，除以 1,000,000 得毫秒/整段。缓存每次重新分配；计时含投影、softmax、汇总、Wo、缓存分配/写入、输出组装和现有统计，输入生成、检查、打印在计时外。

2026-10-19，Python 3.13.3 / NumPy 2.4.6 / scipy-openblas 下，(3,4) 重算/缓存为 0.040355/0.042925 毫秒；额外的 (128,64) 为 4.077775/2.221130 毫秒。两例缓存分别为 192 和 131072 字节。Python 3.14.6 / NumPy 2.4.6 / mkl-sdl 的对应时间为 0.045335/0.047575 和 5.313685/2.664595 毫秒。两个环境数值、容量和计数检查均 PASS；小例子缓存略慢，较大例子缓存较快，不能据此宣称固定加速。较大规模权重除以 sqrt(64)；这是额外对照，非原始要求规定尺寸。

完整输入说明、误差与 9 组测量值见 [本次运行记录](results/kv_benchmark_2026-10-19.md)。所有运行证据属于助手；学习者独立运行与解释仍待验收。
